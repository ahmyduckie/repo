Topic 02

How URLs Work

When someone enters a web address or clicks a link, the browser interprets the URL and uses it to request a resource.

From Address to Web Page

  1. The user opens a URL. The browser reads the address and identifies its components.
  2. The browser identifies the host. If needed, DNS helps translate the domain name into network information used to reach the host.
  3. The browser sends a request. It uses the relevant protocol, such as HTTPS, to communicate with the server.
  4. The server responds. The server processes the request and returns a response, which may contain the requested page or another result.
  5. The browser displays the result. The browser processes the response and presents the page or resource to the user.

Domain Names and DNS

Domain names are easier for people to read and remember than numeric network addresses. The Domain Name System (DNS) helps find the network information associated with a domain name so a browser can contact the correct host.

Example

In https://example.com/help, the host is example.com and the path is /help. The browser uses these parts to determine which host to contact and what resource to request.

Why Standards Matter

URLs follow shared rules so browsers can interpret web addresses in a consistent way. The URL Standard maintained by WHATWG describes how modern browsers parse and process URLs. Consistent rules help websites and browsers work together across different systems.

For more information, visit the WHATWG URL Standard.
